仕様書が提供されています。この仕様書には、その実装方法を記述したチケット群が関連付けられている必要があります。

ゴールは、仕様全体を単一のブランチ上に実装したPRを作成することです。

チケット群は手順のリストではありません。チケット間にブロッキング関係を持つ**タスクグラフ**です。これは、常に着手可能なチケットの**フロンティア**が存在することを意味します。

サブエージェントとのやり取りは疎（最小限）にしてください。主に**コンテキストポインタ**（仕様書、チケット、調査ノート、過去のコミットへの参照）を通じてやり取りを行います。ポインタ経由ですでに利用可能な情報を重複して伝達しないでください。

**実装サブエージェント**は、**最大限の並行性**を確保するため、可能な限りバックグラウンドで実行してください。

## 手順

1. 仕様書とチケット群を読み込みます。タスクグラフを把握できるまで十分に読み込んでください。

2. （任意）チケットで必要とされる調査（関連するコードベースのファイルや外部ドキュメントの調査）を行うために、**探索サブエージェント**を使用します。探索サブエージェントがファイルを保存できることを確認してください。今後起動するすべてのサブエージェントからアクセスできるよう、Markdownの調査ノートはリポジトリ外のディレクトリに保存させる必要があります。これにより、**実装サブエージェント**は探索ではなく実装に集中できます。

3. ブランチを作成し、ドラフトPRを作成します。PRには、仕様書のIssueおよびチケット群をクローズ（解決）対象として指定してください。

4. **実装サブエージェント**を使用して各チケットを実装します。各実装サブエージェントは、それぞれ専用のブランチ上で、専用のワークツリー（worktree）内で作業させる必要があります。

5. **実装サブエージェント**の作業が完了したら、**マージ担当サブエージェント**を使用してその変更をPRブランチにマージします。

6. これにより着手可能なチケットの**フロンティア**が更新された場合は、新たなチケットに着手する**実装サブエージェント**をさらに起動します。これにより最大限の並行性が可能になります。

7. すべてのチケットが完了したら、PRブランチに対して `/code-review` を実行します。コードレビューで指摘されたすべての問題を**実装サブエージェント**で修正します。

8. PRをレビュー準備完了（Ready for review）にします。

9. すべての**実装サブエージェント**のワークツリーをクリーンアップします。

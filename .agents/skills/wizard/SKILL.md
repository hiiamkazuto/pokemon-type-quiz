# ウィザード

**ウィザード**とは、手動で行うと煩雑であり、かつ毎回AIに説明し直すのも手間がかかる手作業の手順について、人間をステップバイステップでナビゲートするBashスクリプトです。各URLを開き、どこをクリックして何をコピーすべきかを正確に指示し、入力された値を受け取って適切な場所（`.env` やGitHub Secretsなど）に書き込み、各ステージで確認を行い、残りステージ数を表示します。サードパーティサービスの設定、単発のデータ移行、あるいはプロジェクトをある状態から別の状態へと移行する際に役立ちます。

洗練されたUXは [`template.sh`](template.sh) によってすでに解決されています（ステージごとの進捗表示、確認ゲート、WSLを含むクロスプラットフォームのURLオープン、機密情報の非表示入力、べき等な `.env` の更新、`gh secret` / `gh variable` の書き込み、完了サマリー）。**エージェントの役割は、手順のスコープを特定し、そのステージ群を記述することだけです。** `STAGES` マーカーより上のライブラリ部分はすべてのウィザードで共通であり、この一貫性こそが重要です。ライブラリ部分を手動編集してはいけません。

ウィザードは原則として使い捨てです。1回の実行のために作成され、スクラッチ領域または `scripts/` に保存され、作業が完了したら削除されます。リポジトリ内に永続化すべき再現可能なセットアップ手順である場合にのみコミットしてください。

## プロセス

### 1. 手順のスコープ確定

人間が行う必要があるすべての手作業のステップと、その過程で取得されるすべての値を洗い出します。何の情報も持たずに質問するのではなく、まずリポジトリを調査してください：

- セットアップの場合: `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、フレームワークの設定ファイル、および `.github/workflows/*`（`secrets.*` や `vars.*` のすべての参照が、ウィザードが生成すべき値となります）。
- マイグレーションや状態移行の場合: 現在の状態、目的とする状態、およびその間にある不可逆なアクション。

その後、ステージの順序付きリストと各ステージが生成する値をユーザーに提示して確認を取ります（ステージの追加、削除、並べ替えが行われる場合があります）。

**完了条件:** すべてのステージが順序通りに定義され、取得される各値について (a) 人間がどこから取得するか、(b) どこに書き込まれるか（`.env`、GitHub Secret、両方、またはいずれでもない純粋なアクション）、(c) 機密情報（非表示入力）か公開値かがすべて判明していること。

### 2. 各ステージの手順のマッピング

各ステージについて、人間が辿る正確な手順を記述します：どのURLを開くか、そこで何を行うか、どこに値が表示されるか、どの環境変数に格納するか（例: 「ダッシュボード → 開発者 → APIキー → テスト用キーを表示 → コピー」）。現在のUIや正確なコマンドが不明な場合は、その旨を明示してユーザーに確認するかドキュメントを調べてください。存在するか不確かな手順を勝手に作り出してはいけません。

**完了条件:** 初見の第三者でも迷わず実行できる具体的な指示がすべてのステージに用意されていること。

### 3. ウィザードの作成

`template.sh` を対象パスにコピーします。サンプルのステージを、依存関係の順序に沿って1ステップにつき1つの `stage` に置き換えます。ライブラリのヘルパー関数（`stage`、`say` / `step`、`open_url`、`ask` / `ask_secret`、`write_env`、`set_secret` / `set_var`、`pause` / `confirm`）を使用し、`TOTAL_STAGES` に作成したステージ数を設定します。

テンプレートの設計基準を維持してください：値を尋ねる前にURLを開く、機密情報には必ず `ask_secret` を使用する、永続化すべき値はすべて `write_env` で書き込む、CIが真に必要とする値のみを `set_secret` に登録する、不可逆なアクションの前には必ず `confirm` を挟む。各 `stage` は画面をクリアして現在のステップのみを表示するため、必要な情報が画面外にスクロールしてしまわないよう、1つのステージには集中すべき1つのタスクのみを収めてください。マーカーより上のライブラリ部分には手を触れず、そのまま保持してください。

### 4. 検証と引き渡し

- `bash -n <script>` を実行し、利用可能であれば `shellcheck` も実行します。
- `chmod +x <script>` で実行権限を付与します。
- エージェント自身でエンドツーエンドの実行を行わないでください（ブラウザが起動し、人間の入力待ちでブロックされるためです）。代わりに静的なトレースによって検証します。ステップ1で洗い出したすべての値が漏れなく取得され、指定された場所に保存されること、および各 `set_secret` の名前がCIの `secrets.*` 参照と完全に一致していることを確認してください。
- ユーザーに実行方法を案内します。再現可能なセットアップ手順である場合はコミットし、READMEからリンクして、次の開発者がAIに質問することなくスクリプトを直接実行できるようにしてください。

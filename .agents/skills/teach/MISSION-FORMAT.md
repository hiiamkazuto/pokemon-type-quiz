# MISSION.md の形式

`MISSION.md` はワークスペースのルートに配置されます。ユーザーがこのトピックを学ぶ*理由*を記録します。すべての指導上の判断（次に何を教えるか、どのリソースを提示するか、どの演習を設計するか）は、このドキュメントに遡れる必要があります。

## テンプレート

```md
# ミッション: {トピック}

## なぜ学ぶのか
{1〜3文。ユーザーが追い求めている現実世界での具体的な目標。このスキルを身につけたとき、生活や仕事で何が変わるか。「Xを理解するため」のような抽象的な表現は避け、その先にある成果を記述してください。}

## 成功の定義
- {ユーザーができるようになる、具体的で観察可能な事柄}
- {もう1つの具体的な事柄}
- {…}

## 制約条件
- {時間、予算、既定の予定、学習スタイルの好みなど、アプローチを縛る制約}

## スコープ外
- {現時点では意図的に追わない隣接トピック — 最近接発達領域（ZPD）を守るための除外事項}
```

## ルール

- **1ワークスペースにつき1ミッション。** ユーザーが無関係な2つの事柄を学びたい場合は、2つのワークスペースを作成してください。
- **抽象的な表現より具体的な表現を重視する。** 「体力をつける」よりも「10月までにハーフマラソンを完走する」。「Rustを学ぶ」よりも「チーム向けにRust製のCLIツールをリリースする」。
- **曖昧な回答には踏み込んで確認する。** ユーザーが理由を明確に言語化できない場合は、書き始める前にヒアリングを行ってください。中途半端なミッションは、ミッションが存在しないことよりも有害です。
- **現実の変化に応じて見直す。** ミッションは変化します。ユーザーの目標が変化した場合は、このファイルを更新してください。古いミッションに今後のセッションが縛られないようにします。
- **簡潔に保つ。** `MISSION.md` が1画面に収まらない長さになった場合、それは羅針盤ではなくただの計画書になってしまっています。

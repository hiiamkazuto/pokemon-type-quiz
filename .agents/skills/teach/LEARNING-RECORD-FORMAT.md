# 学習記録の形式

学習記録は `./learning-records/` 配下に連番（`0001-<スラッグ>.md`、`0002-<スラッグ>.md` など）で保存されます。最初の記録を作成する際にディレクトリを作成してください。

学習記録は指導におけるADR（アーキテクチャ決定記録）に相当します。自明ではない学び、重要な洞察、今後のセッションを左右する既知の前提知識を記録します。最近接発達領域（ZPD）の算出に使用します。

## テンプレート

```md
# {学んだこと・確定した前提知識の簡潔なタイトル}

{1〜3文: 何を学んだか（またはどのような前提知識が確認されたか）、およびそれが今後のセッションにどう影響するか。}
```

これが形式のすべてです。学習記録は単一の段落で構いません。その価値は、「何が既知となったか」および「なぜそれが今後の指導方針を変えるのか」を記録することにあり、形式を埋めることではありません。

## 任意のセクション

真に価値がある場合にのみ追加してください。ほとんどの記録では不要です。

- **ステータス**（フロントマター: `active | superseded by LR-NNNN`） — 以前の理解が誤りであり修正された場合に有用です。
- **根拠** — ユーザーがその理解をどのように実証したか（回答した質問、完了した演習、言及した過去の経験など）。後から検証し直す可能性がある場合に有用です。
- **今後の影響** — これにより今後のセッションで何が解放され、何が除外されるか。自明でない場合に記録します。

## 採番

`./learning-records/` 内の既存の最大番号を確認し、1を加算した番号を使用してください。

## 学習記録を作成するタイミング

以下のいずれかに該当する場合に作成してください：

1. **ユーザーが自明ではない事柄に対して真の理解を示したとき** — 単に触れただけでなく、その概念を正しく使いこなせる証拠が得られた状態。次に何を教えるかの新たな基準となります。
2. **ユーザーが前提知識を明らかにしたとき** — 「Xはすでに知っている」という申告。今後のセッションで重複して教えるのを防ぐために記録します。申告された理解の深さも併せて記録してください。
3. **誤解が解消されたとき** — 以前誤って信じていた事柄について、なぜそれが間違いなのかをユーザーが理解した状態。関連トピックでの今後のつまずきを防ぐ貴重な記録となります。
4. **学習の結果としてミッションが変化したとき** — 当初想定していたこととは異なる関心事にユーザーが気づいた状態。`MISSION.md` へのリンクを貼り、ミッション本文を更新してください。

### 対象外となるもの

- 単に講義で扱っただけの内容（学習が成立した証拠を待ってください）。
- `GLOSSARY.md` にすでに簡潔に定義されている用語（重複して記録しないでください）。
- セッションごとの活動日誌（学習記録は日記ではなく、指導方針の意思決定に直結する洞察です）。

## 記録の差し替え

後の記録が以前の記録と矛盾する場合（ユーザーの理解が深まった、あるいは修正された場合）、古い記録を削除するのではなく `Status: superseded by LR-NNNN` とマークしてください。理解の進化の過程そのものが有用なシグナルとなります。

# スキルの仕組み

[`write-agent-docs`](SKILL.md) のスキル固有の分岐です。ドキュメントがスキルである場合に何が変わるのか（フロントマター、呼び出し方法の選択、ルータースキル）を扱います。それ以外の書き方に関する原則は、すべて `SKILL.md` に記載されている共通のリファレンスに従います。

## 呼び出し方法

2つの負荷（コンテキスト負荷と認知的負荷）をトレードオフにする2つの選択肢：

- **モデル呼び出し型**のスキル：`description` を保持するため、エージェントが自律的に実行でき、他のスキルからも呼び出すことができます。人間がスキル名を入力して呼び出すことも可能です（モデル呼び出し型には常にユーザーからの呼び出しも含まれます。説明文はエージェントによる発見性を追加するだけで、人間からの呼び出しを制限することはありません）。説明文はスキルの最上位コンテキストポインタであり、常に読み込まれ続けるため、発見性と引き換えに永続的なコンテキスト負荷を支払います。すべての内容がリファレンスで構成されたモデル呼び出し型スキルは、共有リファレンスの置き場としても機能します（他のスキルから呼び出せるため、複数スキルが必要とする参照情報を1箇所に集約できます）。実装方法：`disable-model-invocation` を省略し、発動条件となる分岐を含んだモデル向けの説明文を記述します（`SKILL.md` のポインタ記述ルールがすべて適用されます）。
- **ユーザー呼び出し型**のスキル：エージェントから説明文へのアクセスを遮断します。人間が手動で名前を入力した場合にのみ呼び出せ、他のスキルから呼び出すことはできません。コンテキスト負荷はゼロですが、その存在を人間が覚えておかなければならないため認知的負荷を消費します。実装方法：`disable-model-invocation: true` を設定します。`description` は人間向けのもの（トリガーリストを省いた1行要約）になります。

エージェントが自律的にアクセスする必要がある場合、または他のスキルからアクセスする必要がある場合にのみモデル呼び出し型を選択してください。手動でのみ実行されるスキルであれば、ユーザー呼び出し型にしてコンテキスト負荷を支払わないようにします。

2つのユーザー呼び出し型スキルが共通で必要とする参照情報は、どちらのスキル内にも配置できません（説明文がないため、互いを呼び出せないからです）。スキルシステムの外部にある通常のファイルに切り出し、どのスキルからも参照できる外部リファレンスとして配置してください。

## 呼び出し方法による分割

呼び出しの観点による分割（手順の観点による分割は `SKILL.md` を参照）：単独で発動契機とすべき明確な牽引語（プロンプト内で実際に使用するトリガー単語）が存在する場合、または他のスキルからアクセスする必要がある場合に、モデル呼び出し型スキルとして切り出します。常時読み込まれる説明文のためにコンテキスト負荷を支払うことになるため、その独立したアクセス性に十分な価値がある必要があります。

## ルータースキル

ユーザー呼び出し型のスキルが増えすぎて覚えきれなくなった場合、その蓄積された認知的負荷を解決するのが**ルータースキル**です。他のスキルの一覧とそれぞれの使用タイミングを案内する単一のユーザー呼び出し型スキルであり、人間が覚えるべきスキルを1つに集約できます。なお、ルータースキルができるのは案内の提示のみであり、それらのスキルを直接実行することはできません（ユーザー呼び出し型スキルには説明文がないため、人間以外が呼び出すことはできないためです）。

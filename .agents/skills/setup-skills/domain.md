# ドメインドキュメント

コードベースを探索する際に、エンジニアリングスキルがこのリポジトリのドメインドキュメントをどのように利用すべきかを定めます。

## 探索前に読むべきファイル

- リポジトリ直下の **`GLOSSARY.md`**、または
- 存在する場合はリポジトリ直下の **`GLOSSARY-MAP.md`** — コンテキストごとの `GLOSSARY.md` を指し示しています。対象のトピックに関連するものをそれぞれ読んでください。
- **`docs/adr/`** — これから作業する領域に関連するADRを読んでください。マルチコンテキストのリポジトリでは、コンテキスト固有の決定事項について `src/<context>/docs/adr/` も確認してください。

これらのファイルが存在しない場合は、**何も言わずに処理を続行してください**。存在しないことを警告したり、事前に作成を提案したりしないでください。用語や決定事項が実際に確定した時点で、`/domain-language` スキル（`/grill-with-language` や `/improve-architecture` 経由で実行）が必要に応じて後から作成します。

## ファイル構造

単一コンテキストのリポジトリ（大半のリポジトリ）：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

マルチコンテキストのリポジトリ（ルートに `GLOSSARY-MAP.md` が存在）：

```
/
├── GLOSSARY-MAP.md
├── docs/adr/                          ← システム全体の決定事項
└── src/
    ├── ordering/
    │   ├── GLOSSARY.md
    │   └── docs/adr/                  ← コンテキスト固有の決定事項
    └── billing/
        ├── GLOSSARY.md
        └── docs/adr/
```

## 用語集のボキャブラリを使用する

出力内でドメイン概念に言及する場合（Issueのタイトル、リファクタリングの提案、仮説、テスト名など）、`GLOSSARY.md` で定義されている用語を使用してください。用語集が明示的に避けている類義語に勝手に置き換えないでください。

必要な概念がまだ用語集に存在しない場合は、2つの可能性があります。プロジェクトで使われていない言葉を勝手に作り出しているか（再検討してください）、または真の不足があるかです（`/domain-language` 向けにメモしてください）。

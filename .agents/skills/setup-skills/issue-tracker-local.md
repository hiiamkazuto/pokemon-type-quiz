# Issueトラッカー：ローカルマークダウン

このリポジトリのIssueおよび仕様は、`.scratch/` 配下のマークダウンファイルとして管理されます。

## 規約

- 1機能につき1ディレクトリ: `.scratch/<feature-slug>/`
- 仕様書は `.scratch/<feature-slug>/spec.md`
- 実装Issueは `.scratch/<feature-slug>/issues/<NN>-<slug>.md` にチケット1件につき1ファイル（`01` から採番）として配置 — 1つのファイルに複数のチケットをまとめることは絶対に避けてください
- トリアージ状態は各Issueファイルの上部付近にある `Status:` 行に記録（役割を表す文字列については `triage-labels.md` を参照）
- コメントや会話履歴はファイル末尾の `## Comments` 見出しの下に追記

## スキルが「Issueトラッカーに公開する」と指示した場合

`.scratch/<feature-slug>/` 配下に新しいファイルを作成してください（必要に応じてディレクトリも作成）。

## スキルが「関連チケットを取得する」と指示した場合

指定されたパスのファイルを読み込んでください。通常、ユーザーがパスまたはIssue番号を直接指定します。

## 八咫烏の運用

`/yatagarasu` で使用されます。**マップ**は1つのファイルであり、チケットごとに1つの**子**ファイルが対応します。

- **マップ**: `.scratch/<effort>/map.md` — 「メモ」「これまでの決定事項」「不確実な領域」を本文に保持します。
- **子チケット**: `.scratch/<effort>/issues/NN-<slug>.md`（`01` から採番）。本文に問いを含めます。`Type:` 行にチケットの種類（`research`/`prototype`/`grill`/`task`）を記録し、`Status:` 行に `claimed` または `resolved` を記録します。
- **依存関係**: 上部付近の `Blocked by: NN, NN` 行。リストされているすべてのファイルが `resolved` になると、チケットのブロックが解除されます。
- **フロンティア**: `.scratch/<effort>/issues/` をスキャンして、オープンかつブロックされておらず未着手のファイルを探します。番号順で最初のものが優先されます。
- **担当への着手**: 作業を始める前に `Status: claimed` に設定して保存します。
- **解決**: `## Answer` 見出しの下に回答を追記し、`Status: resolved` に設定した上で、`map.md` の「これまでの決定事項」にコンテキストへのポインタ（要約とリンク）を追記します。
